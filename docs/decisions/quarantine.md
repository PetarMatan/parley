| Open point | Choice | Why |
|---|---|---|
| Hook output contract | Guard blocks with exit 2 and the reason on stderr; allows with exit 0 and no output (never auto-allows). Any internal error (bad JSON, missing config, git failure) blocks | Confirmed on code.claude.com/docs/en/hooks (2026-10-28): exit 2 blocks a PreToolUse call and stderr becomes the reason; JSON cannot override an exit 2. Same contract as the harness guard's check command |
| Extra guard hook stdin contract | Hook command = the value of `AIC_EXTRA_GUARD` (a full shell command for an extra PreToolUse hook); it reads the PreToolUse JSON on stdin, exit 2 + stderr on block, exit 0 silent otherwise | Same contract as the harness guard's check command, confirmed with a sample input. `AIC_EXTRA_GUARD` is read at quarantine creation; when it is unset, no extra guard hook is added. Replaces the earlier lookup of the harness guard on PATH |
| Hook matcher | `Bash\|Edit\|Write\|MultiEdit\|NotebookEdit\|WebFetch\|WebSearch\|Read\|Grep\|Glob` | The task list plus `Read`, `Grep`, `Glob`, so secret-file reads through the built-in tools are denied too, not only through Bash |
| Edit target field | `tool_input.file_path`, or `tool_input.notebook_path` for NotebookEdit | Docs confirm `file_path` (absolute) for Write and Edit; MultiEdit and NotebookEdit fields are not on the hooks page, so both names are read |
| Where the guard config lives | `<worktree git dir>/aic-quarantine.json` (inside `clone-b/.git/worktrees/…`), passed as `--config`; holds worktree, work dir, MR branches and the source/target SHAs | Outside the worktree, so the session cannot rewrite it; writes to `.git` are denied and the Claude Code sandbox limits Bash writes to the worktree |
| MR diff for the guard | `git diff --name-only --no-renames <target_sha>...<source_sha>` with SHAs recorded at quarantine creation; cached per session in `<git dir>/aic-guard-diff-<session_id>.json` | SHAs cannot be moved by the session the way refs could. `--no-renames` lists both sides of a rename. Same command shape as the promoter |
| Bash analysis | Own small shell tokenizer: quotes, `; & \| && \|\|`, newlines, `$(…)` and backticks (checked recursively), `sh/bash -c` and `eval` bodies (recursive), wrapper commands (`sudo env timeout xargs nohup …`), redirection targets | A regex over the whole line would block commit messages that mention "push". Anything the tokenizer misreads produces more words, not fewer |
| Bash deny classes | Network tools in command position (curl, wget, nc, ssh, scp, rsync, docker, open, npx, gh, glab, …); git push/fetch/pull/remote/clone/ls-remote/submodule/update-ref/…, `git -c`, `--git-dir`, git config writes; npm/yarn/pnpm/bun/pip/go/cargo/gem install-type subcommands; `python -m pip/http.server`; inline interpreter code (`node -e`, `python -c`, …) naming network or process APIs; any word that is a secret path; any word touching `.git/` or `core.hooksPath`; writes (redirects, cp/mv/tee/sed -i/…) to blocked files or outside the worktree; write targets with `$`, `~`, globs | Task list plus the obvious bypasses. `/tmp`, `/private/tmp`, `/var/folders` and `/dev/null` are allowed write targets only when the target is not inside the worktree (the worktree itself is under `$TMPDIR`) |
| Secret paths | Base names `.env`, `.env.*`, `.envrc`, `*.pem/key/p12/pfx/jks/keystore/jwt`, `id_rsa*` and similar, `.netrc/.npmrc/.pypirc/.pgpass`, `credentials(.json)`, `secret(s)*`, `identity.json`; any path segment `.ssh .aws .gnupg .docker .kube tokens keys` | Covers `.aic/identity.json` and `$AIC_WORK/tokens|keys`. Over-blocks a source folder named `tokens/` or `keys/`; acceptable for the sandbox repo |
| Blocked list copy | `quarantine/blocked.json`, hand-mirrored from `rules.BlockedFiles`; `TestQuarantineBlockedListMatchesRules` in `inbox/internal/promote` fails when they differ. Same glob semantics as `rules.globToRegexp` | No build step in Node; the Go test is the drift alarm |
| Base-branch rule (D16) scope | Every path matching `^.claude/`, `^.mcp.json$` or `(^\|/)CLAUDE(.local)?.md$` (case-insensitive) on either branch is deleted, then restored from the target SHA if it exists there | Claude Code loads nested CLAUDE.md files; an MR-only nested CLAUDE.md is removed |
| Restore without staging | Files are written with `git show <target_sha>:<path>`; the index is untouched. Tracked paths get `skip-worktree`; untracked restored or generated paths go into a per-worktree excludes file (`extensions.worktreeConfig` on clone-b, `core.excludesFile` = `<git dir>/aic-exclude`) | `git checkout <tgt> -- …` would stage the base files and a model's `git commit -a` would carry them into the push. `info/exclude` is shared with clone-b, so a per-worktree excludes file keeps clone-b unchanged |
| Settings overlay | `.claude/settings.json` = target-branch settings + appended PreToolUse guard hooks + union of deny rules + `sandbox` block; `disableAllHooks` removed. `.mcp.json` = target-branch servers + `aic-inbox` pointed at `<repo>/plugin/server.mjs` | Base hooks (SessionStart registration) must keep working; `disableAllHooks` would switch the guard off. Written into `settings.json`, not `settings.local.json`, because in a worktree Claude Code reads the local file from the main checkout (clone-b) |
| Claude Code sandbox, network off | Project settings: `sandbox.enabled`, `failIfUnavailable: true`, `allowUnsandboxedCommands: false`, `network.allowedDomains: []`, `allowLocalBinding: false`. `start-session.sh` also passes `--settings <git dir>/aic-session-settings.json` with `sandbox.network.strictAllowlist: true` | Confirmed on code.claude.com/docs/en/sandboxing (2026-10-28): macOS uses Seatbelt; with an empty allowlist unknown hosts are prompted in default mode, refused only with `strictAllowlist`; `strictAllowlist` is ignored in project files but honored from `--settings`; needs v2.1.219+ (installed: 2.1.303). Hooks and MCP servers run outside the sandbox, so the plugin still reaches the inbox |
| Permission deny rules | `WebFetch`, `WebSearch`, plus `Bash(git push *)`, `Bash(curl *)`, `Read(./.env*)`, `Edit(./.claude/**)` and similar | Second layer under the guard; bare tool name denies the tool |
| Development channel flag | `--dangerously-load-development-channels server:aic-inbox` | Confirmed on code.claude.com/docs/en/channels: dev channels take `plugin:<name>@<marketplace>` or `server:<name>`; the flag is absent from `claude --help` during the preview |
| start-session.sh environment | `env -i` with PATH, HOME, TERM, LANG, CLAUDE_CONFIG_DIR (only when set), plus AIC_WORK and AIC_CHECKOUT=<quarantine> | Task list. HOME is kept so Claude Code finds its login; that means `~` is still readable by the Read tool, only secret patterns are blocked. Gap against "no secrets in home" |
| Re-running make-quarantine | Removes the old worktree (`worktree remove --force`), resets branch `aic/q-<iid>` with `-B` to the current origin head | One quarantine per MR; a stale one would carry old instructions |
| Script fetch | make-quarantine runs `git fetch origin` in clone-b before creating the worktree | "At origin/<source> head" needs current refs. The script runs as B, not as the session |
| Promoter: where the class comes from | `GET /v1/contexts/{ctx}`; the class is taken from `tasks[]` (list or map keyed by task id, field `class` or `finding.class`) or from the task's `finding.v1` payload in `messages[]`. Unknown task or missing class refuses | Contract section 6 does not fix the conversation shape. Inbox stream: please put `class` on each task entry |
| Promoter: check evaluation | Checks 1–6 all run and are all reported; tests run only if all pass; push only if tests pass. Skipped checks are reported with `ok:false` and "skipped" | A full report helps the session reply; no side effect runs after a failure |
| Promoter: input errors | Bad task id, unreadable MR file: a single check named `input` | Contract names no check for it |
| Promoter: origin refs | Fetches `refs/heads/<source>` and `<target>` from `$AIC_WORK/origin.git` into `refs/aic/promote/{source,target}` and pushes to `$AIC_WORK/origin.git` by path, never via the remote named `origin` | The worktree's remote config is in the session's reach in principle; the bare path is fixed. Foundation notes allow using origin.git directly |
| Promoter: fast-forward only | `git push <origin> <sha>:refs/heads/<source>` without `+` or `--force`, after `merge-base --is-ancestor`; `HEAD == source head` refuses as "nothing to promote" | Git refuses a non-fast-forward, also if the branch moved between the check and the push |
| Promoter: running repo code | Every git call sets `core.hooksPath=/dev/null`, `core.fsmonitor=false`, drops inherited `GIT_*` variables; push uses `--no-verify` | The session controls the worktree; its hooks must not run in the promoter process |
| Promoter: test run | Pushes HEAD into a fresh empty repo in a temp dir, checks it out, runs `npm test` with env `PATH, LANG, HOME=<empty>, TMPDIR=<empty>, CI=1, npm_config_offline=true`. On macOS wraps it in `sandbox-exec -p '(version 1)(allow default)(deny network-outbound (remote ip))'` when sandbox-exec exists | The task expected no network enforcement on macOS; sandbox-exec is deprecated but present and works (test `TestSandboxBlocksNetworkInTests`: a localhost connect fails inside it). Without sandbox-exec there is no network enforcement, only the scrubbed env |
| Promoter: policy source | `<worktree>/.aic/policy.json`; missing or `max_patch_lines` ≤ 0 refuses | Task statement. The guard denies edits to `.aic/**`, but the file sits in the session's worktree; a copy outside the worktree would be stronger |
| Promoter: note | After a push, `POST /v1/contexts/{ctx}/notes` as `promoter@aic.local`; a failed note adds a `note` check with `ok:false` but `ok` stays true | The push already happened; `ok` means pushed |
| Promoter: exit codes | 0 pushed, 1 refused, 2 usage | Plugin `inbox_promote` can use the JSON and ignore the code |
| Promoter: base URL | `AIC_BASE_URL`, default `http://127.0.0.1:7070` | Task brief. The plugin's default is the gateway; either works if the promoter token is accepted there |
| Promoter: log | One JSON line per run in `$AIC_WORK/logs/promoter.jsonl`: ts, level (INFO pushed, WARN refused), intLevel, event `promote`, mr, task_id, worktree, outcome, pushed, checks. Secrets are named by pattern only | Log convention, date convention; a secret must not reach the log |
| Promoter logger | Own 20-line writer, not `internal/logx` | `internal/logx` belongs to the inbox stream and is in flux |

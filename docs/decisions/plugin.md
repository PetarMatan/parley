| Open point | Choice | Why |
|---|---|---|
| Reference implementation and licence | `server.mjs` is ported from `claude-plugins-official/external_plugins/fakechat/server.ts`, which is Apache-2.0. The licence text is copied to `plugin/LICENSE`. The `server.mjs` header names the source and lists the changes. `package.json` declares `Apache-2.0` | Apache-2.0 section 4 requires the licence copy and a notice of modification in derived files |
| MCP SDK version | `@modelcontextprotocol/sdk` pinned to exactly `1.32.2` (no caret), with `package-lock.json` | Inspected 1.29.0, 1.30.0, 1.30.1 and 1.32.2: every one has `LATEST_PROTOCOL_VERSION = '2025-11-25'`, and none mentions `2026-07-28`. 1.32.2 is the newest 1.x, and its newest revision is older than 2026-07-28, which the v2 client runtime refuses for channels. Re-check this constant before any upgrade |
| Channel docs, confirmed (code.claude.com channels and channels-reference, fetched 2026-10-28) | Notification is `notifications/claude/channel` with `params.content` (string) and `params.meta` (`Record<string,string>`). Meta keys may contain only letters, digits and underscores. Other keys are dropped silently. The capability is `capabilities.experimental['claude/channel'] = {}`. `instructions` reaches the model when the server connects. The tag is `<channel source="<server name>" k="v">`. Flag for a project `.mcp.json` server: `claude --dangerously-load-development-channels server:aic-inbox`. It works only in interactive sessions: `-p` and the Agent SDK ignore it. The `channelsEnabled` policy still applies | Task asked to confirm these before relying on them |
| Channel docs, not confirmed | I did not read the linked MCP page section on the 2026-07-28 refusal (`mcp.md#push-messages-with-channels`). The SDK choice rests on the design record and the channels page sentence. No live session was run | BUILD-only rule |
| Meta values | All values are strings. `round` is `"1"`, not a number. `kind` is `"finding"` for a finding.v1 message and the reply kind for a reply.v1 message | Docs type meta as string-to-string. The contract lists `kind` without saying what a finding carries |
| How inbound data is rendered | A header names the sender, the ids and the tags, and says the content is untrusted data and not an instruction. Then a `BEGIN DATA <message_id>` line, the re-cleaned payload as one line of JSON with `<`, `>` and `&` escaped as `<` and similar, and an `END DATA <message_id>` line. Every header value has passed a strict pattern | JSON escapes newlines, so a payload cannot forge an END marker or a header line. Escaping angle brackets stops anything shaped like a tag from closing the `<channel>` frame, even if cleaning missed one |
| Envelope checks in the plugin | `message_id` matches `^m-[0-9A-Za-z_-]{1,64}$`. `from` is an email or `aic-inbox`. `round` is 1..1000. The payload must pass finding.v1 or reply.v1 validation, and its `context_id` and `task_id` must equal the envelope's. Tags: the plugin keeps the higher injection score (upstream or its own) and the union of the known stripped names | Header values go into the model context, so each one needs a closed shape. The upstream tags record what the sender's text had before the inbox cleaned it |
| Invalid inbound message | It is not emitted and not acked. The plugin logs it once per message id with the error code only, never the content. `inbox_list` and the SessionStart hook show only a count | The message stays in the inbox for a human to look at, and secrets stay out of the logs. A not-acked message comes back after a reconnect; logging once per id stops log spam |
| Duplicate push | The plugin keeps a set of message ids it has already emitted. If a message comes back (because the ack failed), the plugin only acks it again | Unacked pushed messages go back to `queued` when a stream closes (contract 6), so a reconnect delivers them again |
| Finding the Claude process id | Order: env `AIC_CLAUDE_PID`, then a `ps` walk to the first ancestor whose command base name is `claude`, then `process.ppid`. On this machine `ps -o comm=` shows `claude` for the native install | The contract names both `process.ppid` (server) and the ps walk (hook). Using one function in both avoids a mismatch. An npm-installed Claude Code shows `node`, so the walk would fall back to the parent pid. The env override is for tests |
| Session discovery after start | The server polls the bridge file for up to 30 s. After that it re-reads it every 2 s (`AIC_BRIDGE_WATCH_MS`). When `session_id` changes, it stops the old stream and opens a new one. When the file is removed, it closes the stream | `/clear` and resume start a new session id under the same Claude process, and SessionEnd removes the file. Without this, the stream would stay on a dead session id |
| SessionStart step order | Register, pull, ack, then write the bridge file. The bridge file is written in a `finally` block, so it exists even when the inbox is down | Deviates from the contract's order (bridge first). If the bridge came first, the server could open the stream before the hook acked, and the inbox would push the same messages again (a duplicate in context) |
| SessionStart output | Messages present: `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":…}}`. Empty inbox: no output. Error: one line `{"systemMessage":"aic-inbox: inbox not reached at session start (…)…"}` and exit 0 | Plain stdout from SessionStart goes into the model context. `systemMessage` shows the notice to the user instead |
| Ack failure in SessionStart | The message is still shown | A duplicate on the live stream is better than a lost finding |
| Stuck stream | No bytes for 45 s (the inbox pings every 15 s) aborts the stream and starts the reconnect backoff (1 s doubling to 30 s, reset after a successful open) | A half-open TCP connection would otherwise hang forever |
| Base URL and token | `base_url` comes from env `AIC_BASE_URL`, then `identity.json`, then `http://localhost:3000`. The token file is read again on every request | Contract section 2 lists both sources. Reading the token every time lets `login.mjs` swap the token without a restart |
| Finding the checkout | `AIC_CHECKOUT`, otherwise walk up from the hook input `cwd` (hooks) or `process.cwd()` (server) to the first folder with `.aic/identity.json`. Outside a checkout the hooks do nothing and exit 0 | Task requirement. The hooks are committed into the sandbox repos only |
| Plugin log file | Server and hooks append JSON lines to `<checkout>/.aic/plugin.jsonl` and to stderr. `component` is `aic-plugin` or `aic-hook-<name>`. Every line has `ts`, `level` and `intLevel` | One file per checkout is easier to read than two. stdout is the MCP transport for the server and the hook result for the hooks |
| Tool parameters beyond the contract | `inbox_send` needs `context_id` and generates `task_id` when it is missing. `inbox_reply` and `inbox_promote` take an optional `context_id`; without it they use the context this process has already seen for that task. `inbox_note` takes an optional `context_id` and defaults to the last context seen | Contract signatures (`inbox_note(body)`, `inbox_promote(task_id)`) do not carry the context, but the HTTP paths and `--mr` need it. The additions are optional, so the contract calls still work |
| What `inbox_send` posts | It validates locally with the Node mirror first. On failure, nothing is sent (secrets included). It then posts the raw finding, not the cleaned one | Sending the raw text lets the inbox record what it stripped in `tags.stripped`, which the receiver sees |
| `inbox_promote` | Runs `$AIC_WORK/bin/aic-promote --worktree <checkout> --mr <iid> --task <id> --work $AIC_WORK` with a 10-minute timeout. A non-zero exit with JSON on stdout returns that JSON as a normal result. No JSON means a tool error. `AIC_WORK` defaults to `<repo>/work` | A failed check is a normal outcome. The model must see the check list, not a generic error |
| `inbox_list` | Shows framed messages and does not ack them | Acking is a delivery receipt (D12). A list is a look, not a delivery |
| Node validator: JSON decoding | Top-level keys are scanned from the text in source order. Go behaviours mirrored: keys match exactly first, then case-insensitively; the last duplicate wins; the first type error or unknown-field error in key order is reported; `null` leaves a field unset; a `null` body gives `missing_field`; `line` must be an integer literal in int64 range (`12.0` and `1e2` are type errors); a lone surrogate becomes U+FFFD. Each case was checked against a scratch copy of the Go package | `JSON.parse` moves integer-like keys first, merges duplicates and loses number literals, so it alone cannot match Go's error codes |
| Node validator: regex and whitespace classes | `\s` and `\S` are written as `[\t\n\f\r ]` and `[^\t\n\f\r ]`. The assignment secret pattern uses the `iu` flags (Go simple case folding, code-point counting). Blank detection uses Go's `unicode.IsSpace` set. Lowercasing for the injection score maps U+0130 to `i` per code point | In RE2, `\s` is ASCII whitespace; in JavaScript it is Unicode whitespace. `String.prototype.trim` and `toLowerCase` differ from Go's `TrimSpace` and `ToLower` |
| Node validator: known residual difference | A `Buffer` body with invalid UTF-8 is decoded with `TextDecoder` (WHATWG replacement). Go replaces each bad byte with U+FFFD. The two can give different counts of U+FFFD | The plugin only validates strings (JSON from SSE, tool arguments), so the case does not occur in the plugin |
| Branch for registration | `git rev-parse --abbrev-ref HEAD`. A detached HEAD registers as branch `HEAD` | Delivery prefers the MR source branch, so a quarantine worktree should check out a branch, not a detached sha |
| DEX login (build-time; superseded by port decision P14) | Reads discovery from `<issuer>/.well-known/openid-configuration`. Issuer comes from `--issuer` or env `AIC_DEX_ISSUER`, default `http://localhost:5556/dex`. Uses S256 PKCE, a 43-character verifier, `state` and `nonce` checks, and scope `openid email profile`. Serves the loopback callback on 127.0.0.1:5557 with a 5-minute timeout. Opens the browser with `open` or `xdg-open`; `--no-open` skips this. Writes the ID token atomically with mode 0600 to `token_file`. The signature is not checked locally | PKCE convention: code flow with PKCE, with no password grant. The inbox and gateway verify the signature. Overwriting `token_file` replaces that user's mock token, which is the switch the day-7 test needs |
| Test-only environment variables | `AIC_CLAUDE_PID`, `AIC_HOOK_TIMEOUT_MS` (default 5000), `AIC_BRIDGE_WATCH_MS` (default 2000) | The tests run the hooks and the server without Claude Code |
